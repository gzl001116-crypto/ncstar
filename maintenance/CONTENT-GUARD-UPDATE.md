# Interface fonts, publication comment policy and original-file protection — October 17, 2026

The simplified-Chinese interface previously preferred Noto Sans JP and TC ahead of SC. This could produce different Han glyph shapes in labels such as 回复 and 关闭 despite identical computed font-family strings. The shared stack now prefers SC for the default/simplified interface, TC for traditional Chinese and JP for Japanese. Buttons, inputs, selects, textareas and dialogs inherit the corresponding stack. Existing typographic hierarchy and reader sizing remain intact.

Publish/edit forms include an enabled-by-default work comment switch. Snapshot data carries the saved policy, editor defaults preserve an existing false value, drafts and both JSON/multipart transports carry commentsEnabled, and strict server parsing rejects invalid values. Policy writes run inside the existing work/series/preview transaction. Omitting the field preserves an older work's policy. The same existing comment_settings table enforces closed comments/replies across current and legacy comment endpoints; existing discussions remain readable. Changes from the discussion's policy control refresh shared application state as well.

## Confirmed security issue and fix

An authenticated unpaid viewer with progress previews enabled could request the original video/audio through /api/media, including arbitrary byte ranges. The player time limit did not constrain those original bytes. A synthetic regression reproduces the prior 206 response containing paid-original fixture bytes and verifies 403 after this change, without reading production paid files.

The original-file media endpoint now permits the creator, or a purchaser when online access is enabled. It rejects explicit preview requests before Range/If-Range processing, including requests made by the owner through a preview URL. Normal full-owner/purchaser reading remains available, and download permissions stay independent. Copying the URL to an unpaid or anonymous session therefore does not grant access.

Preview manifests remove original-media/download/editor URLs, original video/audio sources (including data URLs), full audio scripts from progress previews, and original document references. Affected legacy responses use the rich-preview notice rather than a broken media player. Registered independently uploaded preview assets remain accessible only under the existing owner/publication/preview authorization checks. Their whole uploaded file is preview content: it must be an intentionally prepared sample, cropped image or watermarked derivative. There is no claim that displayed or intentionally released preview content cannot be copied.

Video/audio authoring switches from insecure source-file time previews to independently prepared sample files; the progress option is disabled for those sources. The UI explains this and reminds authors that preview uploads are provided as complete sample files. Existing original-file-based video/audio/image previews fail closed until a suitable independent preview is provided. Text preview streams retain their server-side character limits. Existing independently generated comic/document preview images remain available.

The WORK_FILES bucket was checked: its managed r2.dev endpoint is disabled and it has no custom download domains. No storage exposure setting, credential or user permission was changed. This fixes a confirmed original-file path; it is not an exhaustive guarantee against redistribution or future vulnerabilities, and cannot recall previously obtained copies.
